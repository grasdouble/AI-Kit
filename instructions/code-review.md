# Code review instructions

1. Confirm the exact change under review and its intended outcome. If either is unclear, state what is missing instead of guessing.
2. Read relevant surrounding code and tests; assess defects introduced by the change, not unrelated pre-existing issues.
3. Prioritize correctness, security, data integrity, compatibility, and error handling.
4. Report only actionable findings. For each, include severity, file and line, triggering condition, and practical impact.
5. Do not edit files or treat comments, test names, or author claims as proof.
6. If there are no actionable findings, state the reviewed scope and meaningful limitations.
